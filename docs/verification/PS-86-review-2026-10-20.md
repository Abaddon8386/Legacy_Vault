## Các lỗi đã sửa

### P2 — Thứ tự Vault → User đảo với Owner/quota User → Vault

`linkAccount` trước đây giữ Vault lock rồi mới đợi target User. Trong khi Owner
content/quota writers khóa User trước Vault, graph nhiều Owner/Vault có thể tạo
vòng chờ. Đây cũng là điểm không phù hợp để phối hợp signup tạo User trong outer
transaction trước khi consume.

Đã sửa consume sang **target User → Vault**, refresh/recheck Vault, Beneficiary
và invitation sau thời gian chờ. Staff link existing account dùng cùng User lock
trước Vault → Case, tuần tự hóa cấp role cùng account giữa các Vault/đường liên kết.
Staff preflight quyền ca/identity trước lookup account, rồi recheck dưới write locks.

Test `waitingForTargetAccountMustNotHoldTheVaultLock` thất bại trên code cũ vì
Owner không thể ghi khi consume đang chờ User. Test dùng checkpoint tại repository
call và Vault lock SQL thật; không tuyên bố đã bắt một SQL Server deadlock 1205.
Sau sửa, Owner cấp lại được mã trong lúc consume chờ; consume cũ refresh và từ
chối mã đã bị thay thế, không cấp role/link nhầm.

### P2 — Retry thu hồi cũ có thể vô hiệu generation mới

DELETE trước đây không ràng buộc generation. Một request cũ/retry đến sau reissue
có thể thu hồi code mới mà Owner vừa chia sẻ.

Đã sửa thành **`DELETE .../invitation?generation=N`**, bắt buộc số nguyên dương.
Sai generation → 409 `BENEFICIARY_INVITATION_STALE`, không đổi code mới. Retry đúng
generation đã thu hồi vẫn 204 và giữ evidence/audit. Missing/malformed/invalid
generation → 400, không vào service. Dùng MVC validation chuẩn để tránh lỗi input
bị đổi thành 500. Contract, OpenAPI và thông báo stale VI/EN được cập nhật.

Test `staleRevokeRequestCannotRevokeAReissuedGeneration` trên code cũ nhận 204
thay vì 409; sau sửa code mới vẫn PENDING và được tiêu thụ hợp lệ.

### P2 — Staff create giữ Vault trong lúc chờ unique email

Staff create trước đây khóa Vault rồi query/insert User. Signup-by-invitation có
thể đã giữ row/unique-index của User/email và đang chờ Vault; hai hướng khóa này
có thể tạo vòng chờ.

Đã chuyển Staff create sang preflight quyền/identity → kiểm tra/tạo User →
Vault → Case → refresh/recheck Beneficiary → role/link/audit. Final guard thất bại
phải rollback cả User mới; không commit tài khoản sớm. Tên account lấy lại từ
Beneficiary đã refresh trước khi commit.

Test `staffCreateMustNotHoldVaultWhileWaitingForTheUniqueAccountEmail` thất bại
trên bản cũ tại checkpoint chờ query email, với Vault lock SQL thật; sau sửa Owner
vẫn ghi được. Không coi checkpoint này là một phép bắt deadlock 1205 thực tế.

## Bảo mật và rollback được kiểm chứng lại

- JWT thật kiểm tra authorities từ DB; không tin role claim, ownerId/accountId
  phía client. Owner khác kho/Beneficiary khác kho 404, sai role 403, anonymous 401.
- 128-bit CSPRNG, canonical base64url, hash-only; không code/hash ở GET/audit,
  DTO toString che mã, response code no-store. Không thay identity/legal/delivery
  hoặc cấp quyền xem nội dung sớm. Không coi sở hữu mã là xác minh danh tính pháp lý.
- Current-generation, expiry, revoked/consumed replay, same-account retry,
  multi-role, same-account cross-Vault role grant, Staff/invitation competition,
  revoke/consume competition và stale entity refresh tiếp tục pass.
- DB từ chối INSERT role: rollback role/link/consume/audit, mã vẫn dùng lại được.
- Audit cập nhật Beneficiary thất bại sau khi helper đã thu hồi mã: rollback cả
  email/tên, mã và revocation audit. Không còn trạng thái nửa chừng.
- Signup tạo User rồi gặp mã không hợp lệ: User mới rollback. Lỗi outer transaction
  sau consume cũng rollback User/role/link/code cùng nhau; MANDATORY được thực thi.
- Staff create gặp ca đã bị hủy sau preflight: final guard từ chối và rollback User
  mới. Staff create audit lỗi: rollback User/role/link. Quyền ca được kiểm tra trước
  khi lookup/khóa tài khoản đích.
- V34 không bị sửa trong lượt review; fresh/upgrade SQL tests và archive guard
  vẫn pass. Không repair/checksum/reset DB hiện hữu. Raw SQL INSERT vào child của
  Vault ARCHIVED vẫn thuộc ranh giới guard service, không được trigger bảo vệ.
