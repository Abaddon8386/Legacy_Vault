## Confirmed issues fixed

1. **Stale review (PS-102):** reproduced with real HTTP/JWT: a request carrying displayed version 1 returned 200 after version 2 was forwarded. Review now requires reason + versionNo + sha256Hash + allocationHash + disputeStatus from the displayed context. The service locks/refetches Vault -> Case -> Dossier and compares all fields before snapshot/history/audit writes. Missing snapshot is 400; mismatch is 409 LEGAL_DECISION_STALE. Completed review also requires the current forwarded/required version. Supplementation stays reason-only. The String service overload is trusted in-process compatibility only; no HTTP controller uses it.
2. **UTC/DST conversion (PS-108, shared pattern PS-107/102):** a SQL DATETIME2 value 2026-03-08 02:30 became 03:30Z under America/New_York. Replaced java.sql.Timestamp conversions with JDBC 4.2 LocalDateTime for audit bounds/reads, overview DB clock and queue dates. The DST regression changes/restores the JVM timezone and checks exact detail and half-open filter results.
3. **Integration conflicts:** moved the new overview and review-schema OpenAPI blocks to independent locations. Final diffs of all four PRs apply cleanly together without manual conflict resolution. Duplicate YAML keys and all local references are validated. No runtime behavior changed in this layout follow-up.

FE captures the backend-computed snapshot when loading the displayed dossier, submits it unchanged and checks the review receipt against the same version/hash/scope. It never silently fetches a new hash at click time to attest unseen data. Legacy reason-only review clients must upgrade with this change; there is no unsafe fallback.
